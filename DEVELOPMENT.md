# Development status

This file tracks what FeroProbe implements and what is still missing compared
with nmap. **Update it in the same pull request that adds, changes or drops a
feature**, so it stays the one place to see where the project stands.

The goal is nmap parity: FeroProbe behaves like nmap unless nmap's behaviour is
clearly wrong. The deliberate exceptions are listed under
[Not planned](#not-planned), [Anti-abuse safeguards](#anti-abuse-safeguards)
and [Deliberate differences from nmap](#deliberate-differences-from-nmap).
What is still missing, and the order it will be built in, is under
[Roadmap to nmap parity](#roadmap-to-nmap-parity).

Last audited against the source: 2026-11-15 (main at `34559fb`, v0.2.0 plus
the SCTP, IP protocol, IPv6 OS detection and probe-signature work).

## Implemented

### Scan types

| Feature | Options | Notes |
| --- | --- | --- |
| TCP connect scan | `-sT` | No privileges needed; default when not root. Closes open ports' connections with a reset, like nmap |
| nmap's IP header on probes | | Raw scans, discovery and UDP probes: no DF bit, random TTL / hop limit 37-59 per probe (`raw::nmap_ip_header`), as nmap's `build_ip_raw` |
| TCP SYN scan | `-sS` | Raw sockets (Linux, root or `CAP_NET_RAW`); default when root. IPv4 and IPv6 |
| FIN, NULL, Xmas scans | `-sF`, `-sN`, `-sX` | Raw sockets, IPv4 and IPv6 |
| ACK, Window, Maimon scans | `-sA`, `-sW`, `-sM` | Raw sockets, IPv4 and IPv6 |
| Custom TCP flags | `--scanflags` | Names (`SYNFIN`) or a number; answers read like the chosen scan type |
| UDP scan | `-sU` | Service payloads for DNS, NTP, SNMP, SSDP; generic probes carry the FeroProbe marker |
| SCTP INIT and COOKIE ECHO scans | `-sY`, `-sZ` | Raw sockets, IPv4 and IPv6 (`crates/feroprobe-core/src/sctp.rs`) |
| IP protocol scan | `-sO` | Protocol numbers via `-p P:...`, real probes for ICMP/IGMP/TCP/UDP/SCTP (`ipproto.rs`) |
| Ping scan only | `-sn` | Host discovery without a port scan |

| ARP on the local network (IPv4) | default as root, `--disable-arp-ping` / `--send-ip` | MAC address and vendor |
| Neighbour discovery (IPv6) | default as root | MAC address and vendor (`ndp.rs`) |
| MAC vendor names | `--oui-file` | Full IEEE OUI list from the system or a file, small built-in fallback |

### OS detection

| Feature | Options | Notes |
| --- | --- | --- |
| OS fingerprinting | `-O` | Up to 9 probes per try (`os/probes.rs`): 4 SYNs with different option sets 100 ms apart, an ECN SYN and an ACK to an open port; a SYN and an ACK to a closed port the scan found; an ICMP echo only when discovery sends echo requests. The fingerprint (`os/fingerprint.rs`): per-probe flags, window, option layout, DF; TTL, window scale, IP ID sequences, TCP timestamp clock, ECN. IPv4 and IPv6, answers read off an `AF_PACKET` capture |
| OS database | | Our own (`crates/feroprobe-core/data/os-fingerprints.txt`, format in `docs/os-fingerprints.md`): Linux 2.6 / 3.x-4.18 / 4.19-6.x, Windows XP / Vista-8.1 / 10-11, macOS, FreeBSD, OpenBSD, Cisco IOS, embedded (lwIP-like) stacks. Weighted matching (`os/db.rs`), perfect match = 100%, guesses from 85%. Only the Linux signatures are verified against captures so far |
| OS options | `--osscan-limit`, `--osscan-guess` (`--fuzzy`), `--max-os-tries` | As in nmap: tries repeat until a perfect match, at most 2 when conditions are not ideal |
| OS report | | nmap's layout: `Device type`, `Running`, `OS CPE`, `OS details` / `Aggressive OS guesses`, the `OS:` fingerprint, `Network Distance`, `IP ID Sequence Generation` (`-v`); XML `<osmatch>`/`<osclass>`/`<cpe>`/`<osfingerprint>`/`<ipidsequence>`; grepable `OS:` |
| Network distance | | 0 for this machine, 1 with a known MAC address, else from the TTL |
| Aggressive mode | `-A` | `-sV -O --traceroute`; only `-sV` without raw-socket privileges, with a warning naming what was skipped |

### Timing and performance

| Feature | Options | Notes |
| --- | --- | --- |
| Timing templates | `-T0` … `-T5` (or names `paranoid` … `insane`) | Set the RTT timeouts (nmap's values), retries, parallelism, rate and scan delay (`timing.rs`); explicit flags override; a repeated `-T` takes the last one, like nmap |
| Adaptive probe timeouts | `--min-rtt-timeout`, `--max-rtt-timeout`, `--initial-rtt-timeout` | nmap's `adjust_timeouts2`: per-host smoothed RTT and variance (RFC 6298), timeout = srtt + 4·rttvar clamped to min/max and at least the scan delay; a host without answers borrows the run-wide estimate, else the initial timeout. Setters move each other like nmap's. One `RttState` per run (`rtt.rs`), so the port scan, OS detection, `-sV` connects and traceroute start from what discovery measured. ARP/NDP answers do not feed it; reverse DNS to `--dns-servers` waits the initial timeout, at most 5 s (the system resolver keeps its own) |
| Congestion control | | nmap's `ultra_timing_vals`: a window per host and one per scan, start 10, slow start to 75 then congestion avoidance, `cc_scale`, cut on an answer to a resent probe (host to 1, group halved), once per batch; ICMP errors to resends ignored when silence means filtered; group window only with 2+ hosts left. In the raw TCP, SCTP, IP protocol (`rtt::Flight`), connect and UDP (`rtt::AsyncWindow`) engines. Never sends faster than `--max-rate`/`--scan-delay`; `--min-rate` passes a full window |
| Probe timeout and retries | `--timeout`, `--retries` (nmap's name `--max-retries` too) | `--timeout` fixes all three RTT timeouts (FeroProbe's own). Retries are a cap, as in nmap (`allowedTryno`): one resend until a host answers a resent probe, then one more than its highest answered try, up to `--max-retries` (10; 6 at `-T4`, 2 at `-T5`). Raw scans keep probes out of tries on a bench and send them again when the cap rises (`retransmitBench`); connect and UDP probes are not. Resends go before new probes, and a host's first resend of each try number waits out a one-second pause (nmap's rate limit detection, `RLD_TIME_MS`). Raw TCP probes carry their try number in the sequence number, so an answer is timed against the try it answers. ARP, ICMP echo, OS detection, traceroute and DNS resend once (`ScanConfig::first_retries`) |
| Parallelism | `-c`, `--concurrency` (nmap's names `-M`, `--max-parallelism` too), `--min-parallelism` | Caps the congestion windows, and `--min-parallelism` sets their floor (nmap's `low_cwnd`); also the connect and UDP sockets open at once. At least 1, nmap's warnings and its min > max error |
| Packet rate | `--min-rate`, `--max-rate` | `--max-rate` (no default, as nmap; until 2026-11-16 templates capped it, 5000/s for -T3) caps raw-socket probes (SYN, ICMP, ARP, NDP) on one schedule shared across the run, catching up on slots lost to oversleeping; connect and UDP probes are paced by `--scan-delay` and bounded by the congestion windows and `--concurrency`. `--min-rate` raises `--max-rate` and the connect/UDP parallelism, shortens a template's scan delay, and lets probes through a full congestion window when the scan falls behind |
| Delay between probes | `--scan-delay`, `--max-scan-delay` | A per-host delay, raised as nmap's `boostScanDelay` does: over 10 answers to resends making up more than 30 % (40 % at `-T4`/`-T5`) of answers since the last change, or an answer only after more than 3 (4) resends; 5 ms first (50 ms UDP), doubling to 1 s, capped by `--max-scan-delay` (10 ms TCP at `-T4`, 5 ms at `-T5`), never below `--scan-delay`. No timing pings, no `-v` messages |
| Per-host time limit | `--host-timeout` | |
| Progress | `--stats-every`, `-v`, `-vv` | |
| Benchmarks | | criterion benches in `crates/feroprobe-core/benches` |

### Interface and source port

| Feature | Options | Notes |
| --- | --- | --- |
| Interface | `-e` | Every socket of the run is bound to it (`netif::use_interface`, `netif::bind_socket`): raw sockets, the `AF_PACKET` capture, ARP and NDP, connect, UDP, `-sV` and the `--dns-servers` resolver. Source address from the interface; only its networks are local. Linux and macOS |
| Source port | `-g`, `--source-port` | Raw TCP/SCTP/IP-protocol scans, raw TCP and UDP pings, OS detection (`raw::probe_sport`) and UDP scan sockets (shared with `SO_REUSEADDR`, bound on the route's source address). Not for connect scans (nmap's warning), `-sV`, traceroute, DNS, as in nmap. `-g 0` warns; UDP cannot use port 0. nmap-diff cases `source-port*`, `interface-*` |

### Anti-abuse safeguards

| Feature | Notes |
| --- | --- |
| Recognizable probe signature | Raw TCP scans use window 65109 (`0xFE55`); generic UDP probes carry `FeroProbeScan/1\n`; ICMP/ICMPv6 echo requests carry `feroprobe` (`packet::ECHO_MARKER`). Documented in `docs/responsible-use.md` |
| IDS rules | Suricata (`rules/feroprobe.rules`) and Snort (`rules/feroprobe.snort.rules`) |
| Settings files | `~/.config/feroprobe/config.toml` (XDG), under sudo also the invoking user's (`SUDO_USER`), then `./.feroproberc`; CLI wins; `-v` shows what was read. FeroProbe's own, nmap has none. `crates/feroprobe-cli/src/config.rs` |
| ICS protection | `ics_protection = true` refuses `-sV`, `-O`, `-A` (future script scanning too); `--override-ics-protection` allows one run with a warning; `--dry-run` is not refused but warns; warns on OT ports 102, 502, 20000, 44818, 47808. Off by default, so nmap behaviour is unchanged; Cargo feature `ics-protection-default` builds it always on (files cannot switch it off). `docs/ics-protection.md` |
| Evasion options behind an authorization flag | `-f`, `--mtu`, `-D`, `-S` (raw IPv4 TCP scans). Private ranges (RFC 1918, loopback, link-local, CGNAT, IPv6 ULA) work as is; a public target, decoy or spoofed source needs `--allow-public-evasion` (`scope.rs`, `evasion.rs`) |

## Deliberate differences from nmap

| Behaviour | nmap | FeroProbe | Why |
| --- | --- | --- | --- |
| `--packet-trace` with `-f`/`--mtu` | Prints one `SENT` line for the whole, unfragmented probe, although the fragments are what goes on the wire | Prints one `SENT` line per fragment actually sent (`TCP ... (frag)`, then `IP ... frag offset=N`) | The trace should show what is sent; nmap's display is treated as a bug and not copied (Jurgen, 2026-11-15). `--dry-run` shows fragments the same way |
| Evasion against public addresses | Allowed | Needs `--allow-public-evasion` | Anti-abuse safeguard, see `docs/responsible-use.md` |
| Probes outside the requested ports | `-A`'s scripts probe other ports (`ms-sql-info` sends a 1-byte UDP datagram to 1434 on every host, seen in Jurgen's tcpdump of `nmap -A -p 502,102`); `-O` picks a random UDP port, and for IPv4 also TCP (30000-44780, regardless of `-p`), when the scan found no closed or unfiltered one | Never. `-sV` probes only open ports the scan found; `-O` probes an open TCP port the scan found and, when it found one, a closed TCP port (plus an ICMP echo only when discovery sends echo requests); there are no scripts. Traceroute falls back to a TCP port of the command: a scanned port, the `-p` port with `-sn` (even with `-Pn`, where nothing else probes it), or a discovery port, else skips the host with a warning (it used to fall back to port 80) | An OT operator must be able to rely on the command's ports (`-p` plus the documented host-discovery ports, which `-Pn` or `-P*` control) being the whole scope (Jurgen, 2026-11-15). When script scanning is added, scripts must default to the scanned ports (like nmap's `mssql.scanned-ports-only`) |
| `-A` without root | Silently drops `-O` and traceroute | Drops them too, with a warning naming them and why | No silent downgrade (Jurgen, 2026-11-15) |
| UDP service payloads (`-sU`) | nmap's payload database: several probes per port (two DNS queries to 53, two NTP versions to 123, SNMPv1 and v3 to 161, three NetBIOS queries to 137) | FeroProbe's own, one per port (DNS, NTP, SNMP, SSDP), else `FeroProbeScan/1\n` | nmap's payloads cannot be redistributed; found by `scripts/nmap-diff` and kept (Jurgen, 2026-11-15) |
| ICMP echo payload | Empty | The 9 bytes `feroprobe` | Part of the probe signature, so defenders can match discovery pings; found by `scripts/nmap-diff` and kept (Jurgen, 2026-11-15) |
| OS detection probes (`-O`) | About 16 probes per try (with a UDP probe, T3/T5-T7 odd flag combinations and 2 ICMP echoes), random closed ports between 30000 and 44780 when the scan found none, and hosts without an open port probed too | At most 9 probes per try, only to the open and closed TCP ports the scan found, the echo only when discovery sends echo requests; hosts without an open TCP port get none | Lighter on the target and stays inside the command's scope; found by `scripts/nmap-diff` and kept (Jurgen, 2026-11-15), probe count kept well under nmap's in the 5.2 multi-probe design |
| OS uptime and TCP sequence lines (`-O -v`) | `Uptime guess` from TCP timestamps, `TCP Sequence Prediction` | Not printed | Current Linux, macOS and FreeBSD give each connection a random timestamp offset, so nmap's uptime for them is wrong |
| `-sV` probe order | Sends the `NULL` probe (listen, up to 6 s) first on every port, then the probes registered for the port | Sends the probes meant for the port first, then listens; inside TLS it listens only on talk-first ports (465, 993, ...) | Saves a 3 s wait on every HTTP and other client-speaks-first port. Kept from before the rules file; up to Jurgen whether to follow nmap here |
| `-sV` on industrial protocols | Its database has probes for some industrial protocols | No probes for Modbus, S7 and the like; on those ports `-sV` sends only the generic probes (listen, HTTP and the others up to the intensity) | A version probe is a request the device must parse; see `docs/ics-protection.md` |
| Comparing reports (`feroprobe-diff` vs `ndiff`) | Pairs hosts by first address and first name together, so a renamed host shows as one host gone and one new; sorts addresses as text (10.0.0.10 before 10.0.0.2); ignores an SSL tunnel change (`http` to `ssl/http`); leaves pre- and post-scan script changes out of the exit status; prints local time | Pairs hosts by address, so a renamed host shows once with its old and new name (as ndiff's own manual shows it); numeric address order; a tunnel change is a change; script changes count; UTC | ndiff's behaviour looks like bugs; listed in `docs/feroprobe-diff.md`. Kept (Jurgen, 2026-11-16) |
| Dry run | No equivalent. The closest is the list scan `-sL`, which only lists (and reverse-resolves) the targets | `--dry-run` lists every probe, per target and port, without sending any, and does no reverse DNS | A safe way to check exactly what a command would put on the wire. It lists FeroProbe's probes only. The manual's `--dry-run` section documents what nmap sends differently per option; an in-output "not nmap" box was tried and dropped (Jurgen, 2026-11-15) |

## Roadmap to nmap parity

Every remaining gap to nmap is planned, except the items under
[Not planned](#not-planned). The steps are in order of importance, and each
step is one pull request (or a few, where noted) that also updates this file,
`docs/manual.md`, the man page and `--help`. A step that adds a probe follows
the scope rule (no probes outside the command's ports and protocols, see
[Deliberate differences](#deliberate-differences-from-nmap)) and adds a
`--dry-run` line for it, and a step that changes what goes on the wire gets an
`scripts/nmap-diff` case.

### Phase 5: v0.4.0

Released as v0.4.0 (2026-11-16) with 5.1 (first pull request), 5.2, 5.3,
5.4 and the tuning names of 5.5, plus nmap's default port lists and top-ports
order. Still open from this phase: more `-sV` protocol batches (5.1) and host
groups (5.5), which ships with `--resume` in v0.5.0.

| Step | Feature | nmap options | Plan |
| --- | --- | --- | --- |
| 5.1 | Deeper version detection | `--version-intensity`, `--version-light`, `--version-all`, `--version-trace` | Move the rules in `service/rules.rs` into a data file in our own format (probe, ports, rarity 1-9, match and soft-match patterns, version and CPE fields), compiled into the binary and overridable with a file, like `--oui-file`. Intensity picks probes by rarity, as nmap does. `--version-trace` prints each probe and reply. Then grow the rule set protocol by protocol from public protocol documentation and our own captures (never from `nmap-service-probes`). Several pull requests: the format and options first, then batches of protocols. **First pull request done:** the format, the options, `--service-rules`, the Service Info line and CPEs, `open\|filtered` UDP probing, and a first batch (37 probes, about 150 rules). Next: more protocol batches |
| 5.2 | Full OS fingerprinting | `--osscan-limit`, `--osscan-guess`, `--max-os-tries` | **Done.** A multi-probe fingerprint of our own design (TCP option and window tests to the open port and, where the scan found one, a closed port; IP ID sequence), sent only to ports and protocols the scan already probed (an ICMP test only when the command already sends ICMP, such as default discovery or `-PE`), with our own signature file naming OS versions where the probes can tell them apart. Keeps the [lighter-than-nmap difference](#deliberate-differences-from-nmap) as far as possible: the probe count is documented and stays well under nmap's. `--osscan-limit` skips hosts without an open and a closed port, `--osscan-guess` prints near matches, `--max-os-tries` sets the retries |
| 5.3 | Adaptive RTT timeouts | `--min-rtt-timeout`, `--max-rtt-timeout`, `--initial-rtt-timeout` | **Done.** Per-host smoothed RTT and variance (nmap's and TCP's RFC 6298 formula), timeout = srtt + 4·rttvar clamped to the min and max; the `-T` templates set the three values as nmap's do. `--timeout` stays as FeroProbe's fixed-timeout option and sets all three. Also nmap's congestion windows, adaptive retransmission count (up to 10) and automatic scan-delay increase on heavy loss (`--max-scan-delay`). Not done: nmap's timing pings |
| 5.4 | Interface and source port | `-e`, `-g` / `--source-port` | **Done** (see [Interface and source port](#interface-and-source-port)). `-e` binds raw, capture, ARP/NDP and connect sockets to the interface (`netif.rs`). `-g` sets the source port on raw TCP/UDP/SCTP probes and binds UDP sockets to it, with nmap's caveats (DNS lookups and some OS detection probes keep their own ports; connect scans cannot reuse one port for parallel connections) |
| 5.5 | nmap's names for tuning options | `--max-retries`, `--min-hostgroup`, `--max-hostgroup`, `--min-parallelism`, `--max-parallelism` | **Names done**: `--max-retries`, `-M`/`--max-parallelism` and `--min-parallelism`. **Host groups still to do** (`--min-hostgroup`, `--max-hostgroup`), in their own pull request since they change how results are reported. `--max-retries` as an alias of `--retries`, `--max-parallelism` of `-c`; host groups become real (scan hosts in groups and report each group as it finishes, as nmap does). Our own names stay |

### Script engine design

**Language.** Lua 5.4, embedded with the [`mlua`](https://crates.io/crates/mlua)
crate (MIT) and its `vendored` and `async` features, so the Lua interpreter
(MIT) is built into the binary on Linux, macOS and Windows and script I/O
runs on the same tokio runtime as the scan. Lua because script authors know it
from nmap, it is small, and it sandboxes well. A pure-Rust interpreter would
avoid the C build but none is mature enough yet. Rhai was considered earlier
and rejected because it is not what nmap users write.

**Script format.** Same shape as an nmap script, so the model is familiar: a
`.lua` file with `description`, `author`, `license`, `categories`, one or more
of `prerule`, `hostrule`, `portrule`, `postrule`, and an `action` function that
returns a string or an output table. The libraries live in our own namespace
(`fero.socket`, `fero.shortport`-like helpers under our own names, `fero.http`,
`fero.output`, `fero.args`, `fero.registry`), designed and documented by us.
nmap's scripts will not run unchanged, because they depend on nmap's own
libraries (`stdnse`, `shortport`, `http`, …), which FeroProbe cannot ship (see
[Licence](#licence-caveats)).

**Selection.** `--script` takes script names, file or directory paths,
categories and boolean expressions (`"default and safe"`, `"not intrusive"`),
like nmap. `-sC` means `--script default`. Users can load their own scripts
from a path; FeroProbe's own live in a `lua-scripts/` directory in the repository
(name to be settled) and are compiled into the binary.

**Sandbox.** Scripts get Lua's `string`, `table`, `math`, `utf8` and coroutine
libraries, and FeroProbe's libraries. No `io`, `os.execute`, `package.loadlib`
or `debug`, and file reads only through an explicit library call limited to
`--script-args` files. Each script run has a memory limit, an instruction limit
and `--script-timeout`.

**Scope (no surprises).** Script sockets are checked by the engine, not by
trust in the script: by default a script may connect only to the host it runs
on and only to the ports the scan probed, like nmap's
`mssql.scanned-ports-only` but for everything. A wider scope needs an explicit
option (name to be settled, e.g. `--script-scope=host`). `--dry-run` lists
the candidate scripts for each host and port and the scope each one is
allowed, without running them. It cannot say which of them will actually
run, because a `portrule` usually depends on what the scan finds. It cannot list a script's individual
requests, because a script picks them from the replies it gets; the dry-run
section of the manual says so.
Discovery-style `prerule` scripts that broadcast are off unless named
explicitly.

**ICS protection.** With `ics_protection = true`, every script run is refused
(`-sC`, `--script`, and the scripts `-A` adds) unless
`--override-ics-protection` is given, the same as `-sV` and `-O` today.
`--dry-run` is not refused but warns.

**Signature.** Script traffic is ordinary application traffic, so the raw-probe
markers cannot apply. The HTTP library sends a `User-Agent` naming FeroProbe's
script engine, as nmap's does, and `docs/responsible-use.md` documents what
script traffic looks like.

**Output.** Normal output under each port or host like nmap's `|_` lines;
`<script id output>` elements with `<elem>`/`<table>` in XML, as nmap's;
structured results in JSON.
